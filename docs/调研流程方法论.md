# 调研流程方法论

> 从"中老年赛道"和"豫剧赛道"两次完整调研中蒸馏出的通用调研方法流程
> 版本: v1.0 | 日期: 2026-05-14
> 适用: 任何垂直内容赛道的数据获取、分类蒸馏与调研资产建库

---

## 核心原则

**一句话：赛道不同，骨架相同，数据替换，关键适配。**

调研阶段的工作重心是**数据获取与分类蒸馏**——用正确的采集策略拿到足够原始数据，再用统一的12维度骨架将数据蒸馏为结构化参考文件。每个赛道的数据不同，但蒸馏骨架一致；在骨架的关键节点上做赛道特有适配。

---

## 全流程总览

```
赛道定义 → 网络采集 → 竞品专项采集 → 数据蒸馏建库 → 12维度+赛道特有维度 → 迭代补充
```

调研阶段只关注数据获取和分类，不涉及内容创作流程。蒸馏产出的 `references/` 文件和 `SKILL.md` 是调研的终态交付物，创作使用是下游工作。

---

## 第一阶段：赛道定义

### 步骤1：明确赛道核心定位

在动手采集前，先回答4个问题写成赛道定义：

| 问题 | 思考方法 | 示例 |
|------|---------|------|
| 目标人群是谁 | 不是简单标签，是"与赛道主题的关系类型" | 中老年=按年龄，豫剧=按关系深度 |
| 他们最关心什么 | 列出该人群在赛道内的核心关注方向 | 养生7品类 vs 豫剧11品类 |
| 品类体系怎么分 | 生活类少而宽(5-8)，专业类多而深(10-15) | 7 vs 11 |
| 受众分层逻辑 | 关键差异维度决定分层方式 | 年龄段 vs 关系类型 vs 地域 vs 专业程度 |

### 步骤2：确定品类体系

品类是数据分类的骨架，决定了后续采集维度和蒸馏文件的切分方式。

| 赛道类型 | 品类数量 | 子品类深度 | 示例 |
|----------|---------|-----------|------|
| 生活类（养生/育儿/职场） | 5-8个 | 每品类3-5子项 | 中老年7品类 |
| 专业类（戏曲/编程/茶道） | 10-15个 | 每品类5-10子项 | 豫剧11品类 |
| 混合类（健身/美食） | 8-12个 | 每品类4-7子项 | - |

每个品类必须定义：
1. **品类名称**
2. **子品类列表**（至少3个）
3. **高度兼容品类**（哪些品类经常一起出现，用于后续交叉维度）

## 第二阶段：网络数据采集

### 步骤3：firecrawl批量搜索采集

**工具：** firecrawl-search（多轮主题搜索） + firecrawl-scrape（深度页面抓取）

**核心策略：按品类维度逐维度搜索，每个维度2-5轮关键词**

#### 搜索维度规划

搜索维度分为**必搜维度**和**按赛道类型选搜维度**：

**必搜维度（所有赛道都要搜）：**

| 维度 | 关键词模板 | 产出目标 |
|------|-----------|---------|
| 赛道百科概述 | `"{赛道名}百科 历史 概述"` | 百科主词条数据 |
| 受众画像 | `"{赛道名}受众 观众 用户画像 调研"` | 受众分层依据 |
| 竞品账号 | `"{赛道名}公众号 自媒体 竞品 热门账号"` | 竞品数据 |
| 爆款内容 | `"{赛道名}爆款 热门内容 选题 热门标题"` | 爆款模式 |
| SEO关键词 | `"{赛道名}关键词 SEO 百度指数 搜索热度"` | 长尾关键词 |
| 新媒体传播 | `"{赛道名}短视频 抖音 B站 年轻人 传播"` | 传播数据 |

**按赛道类型选搜维度：**

| 赛道类型 | 需要额外搜索的维度 | 关键词模板 |
|----------|-------------------|-----------|
| 专业类 | 核心品类专项（每个品类1-2轮） | `"{品类关键词}"` |
| 专业类 | 历史沿革 | `"{赛道名}历史 发展沿革 演变"` |
| 专业类 | 传承创新 | `"{赛道名}传承 创新 当代发展 新趋势"` |
| 地域性 | 地域差异 | `"{赛道名}地域差异 地方特色 区域"` |
| 艺术类 | 名家/流派 | `"{赛道名}名家 流派 代表人物 传记"` |
| 艺术类 | 经典作品 | `"{赛道名}经典作品 代表作 名作"` |
| 艺术类 | 技术体系 | `"{赛道名}技术体系 方法 理论"` |

#### 搜索轮次数量估算

| 赛道类型 | 必搜轮次 | 选搜轮次 | 总计 |
|----------|---------|---------|------|
| 生活类 | 6轮 | 4-9轮 | 10-15轮 |
| 专业类 | 6轮 | 14-29轮 | 20-35轮 |
| 混合类 | 6轮 | 9-19轮 | 15-25轮 |

#### 搜索实操要点

1. **每轮搜索记录5个URL + 抓取状态**，为后续scrape筛选提供依据
2. **优先抓取百科词条、Wikipedia、权威媒体**——这些是数据蒸馏的主原料
3. **遇到anti-bot拦截记录为"抓取失败"**，后续用browser-harness交互式补抓
4. **所有原始数据存入 `原调研资产/.firecrawl/`**，文件命名规则：`{搜索主题}-{来源}.json` 或 `.md`

### 步骤4：深度页面抓取

从搜索结果中挑选高质量页面进行scrape。抓取优先级：

| 优先级 | 页面类型 | 原因 |
|--------|---------|------|
| P0 | 百度百科/Wikipedia主词条 | 数据最全面，是蒸馏的主数据源 |
| P1 | 百度百科/Wikipedia子词条（流派/人物/事件） | 提供品类专项数据 |
| P2 | 权威媒体深度文章 | 补充细节和叙事素材 |
| P3 | 政府官网/行业协会 | 提供官方数据和纪念日 |
| P4 | 知乎/搜狐等平台文章 | 补充视角，但质量需甄别 |

**抓取失败处理：** 记录失败URL和原因，用browser-harness在步骤5中交互式补抓。

### 步骤5：browser-harness竞品专项采集

> **操作细节参阅：** [搜狗微信搜索内容调研操作流程](./搜狗微信搜索内容调研操作流程.md) — 该文档提供了使用 agent-browser 进行搜狗微信搜索的完整操作SOP，包括每一步的命令示例、翻页采集方法、图片懒加载处理、Tab管理铁律和反爬应对策略。执行本步骤前必须先阅读该文档。

搜狗微信搜索是竞品数据的主要来源，需要交互式操作：

**采集流程：**

1. 用browser-harness打开搜狗微信搜索（https://weixin.sogou.com）
2. 每轮输入关键词，翻页采集公众号文章标题、账号名、阅读量等
3. 多轮搜索覆盖不同角度（赛道名+各品类关键词+热门话题）
4. 将采集结果整理存入 `原调研资产/搜狗微信搜索原始记录.md`

**必须采集的竞品维度：**

| 维度 | 搜索关键词示例 | 产出 |
|------|---------------|------|
| 赛道总览 | "{赛道名}" | 总文章数量 |
| 品类专项 | "{品类关键词}" | 各品类文章量分布 |
| 爆款传播 | "{赛道名}爆款 热门" | 爆款标题模式 |
| 地域/人物 | "{地方/人物关键词}" | 竞争空白发现 |

**产出：** 竞品账号数据 + 标题示例集 + 传播量化指标 + 竞争空白分析

**豫剧赛道实际采集记录：**
- 豫剧关键词总搜索结果：约7,921条公众号文章
- 豫剧经典名段：约1,000条
- 抖音播放量：5.1亿+
- 竞品账号：9个详细数据
- 确认6种完全未被使用的标题类型（竞争空白）

## 第三阶段：数据蒸馏与分类建库

这是调研的核心产出环节。将原始抓取数据蒸馏为结构化YAML/MD参考文件，按12维度分类体系组织。

### 步骤6：构建12维度参考数据体系

12维度是两个赛道验证过的**最小完整分类集合**。每个维度对应一个参考文件，数据来源明确，字段定义统一。

#### 蒸馏原则

1. **按需蒸馏，不是照搬**——百科词条的"历史渊源"不是直接复制，而是提取关键节点转化为"内容创作角度"
2. **每个数据点增加"创作切入角度"字段**——这是从"百科数据"到"创作资源"的关键转化
3. **结构优先于内容量**——YAML的字段结构比条目数量更重要，结构决定后续SKILL.md能否正确引用
4. **按需加载设计**——每个文件标注"何时读取"，SKILL.md不会一次全读

#### 维度1：受众画像矩阵

**文件：** `{赛道名}受众画像矩阵.yaml`

**数据来源：** 无直接网络数据，基于赛道定义推导 + 竞品数据验证

**必含字段：**

| 字段 | 说明 | 数据来源 |
|------|------|---------|
| 受众类型定义 | 核心特征 + 核心心态 | 推导+竞品验证 |
| 品类关注度排名 | 每类受众×各品类的关注度等级 | 推导+竞品验证 |
| 切入角度 | 每类受众×每品类的最佳切入点 | 推导 |
| 内容演变线 | 每类受众在该品类的进阶路径 | 推导 |
| 禁忌 | 每类受众不应触犯的内容禁忌 | 推导+竞品验证 |

**适配要点：** 受众分层方式必须根据赛道特性决定。中老年按年龄段（3档），豫剧按关系深度（5类）——不要强行用年龄段。

#### 维度2：内容品类交叉矩阵

**文件：** `{赛道名}内容品类交叉矩阵.yaml`

**数据来源：** 基于品类体系推导

**必含字段：**

| 字段 | 说明 |
|------|------|
| 子品类列表 | 每品类的子项 + 高度兼容品类 |
| 受众类型 | 对应受众画像矩阵 |
| 时令周期 | 引用全年日历 |
| 专项事件 | 赛道特有周期性事件 |
| 3种选题公式 | 基础/事件/交叉 |
| 跨品类交叉组合 | 6组：推导公式+标题交叉模式+示例选题 |
| 多样性规则 | 每批选题覆盖不同品类和受众 |

**适配要点：** 交叉组合必须根据赛道的品类逻辑设计。中老年是"养生×家庭""家庭×退休"等生活类交叉，豫剧是"流派名家×经典剧目""河南文化×经典剧目"等专业类交叉。

#### 维度3：全年节庆纪念日日历

**文件：** `{赛道名}全年节庆纪念日日历.yaml`

**数据来源：** 通用节气节日 + 赛道专项纪念日（从搜索和百科中提取）

**必含字段：**

- 52周按四季分组（春15/夏13/秋11/冬13）
- 每周：日期 + 节庆/时令 + 每类受众的选题方向 + 时令标签
- **赛道专项纪念日单独列出**——这是通用日历之外必须补充的维度

**适配要点：** 每个赛道有自己的专项纪念日。中老年没有专项日，豫剧有5月20日非遗日、名家逝世纪念、豫剧艺术节、梨园春年度赛等。

#### 维度4：生命事件维度

**文件：** `{赛道名}生命事件维度.yaml`

**数据来源：** 基于赛道受众特性推导

**必含字段：**

- 15个左右事件触发器
- 每个事件：触发场景 + 情感关键词 + 适用受众 + 选题方向

**适配要点：** 事件类型取决于赛道受众与主题的关系。中老年的事件是退休/丧偶/带孙等"生活变故"，豫剧的事件是回乡看戏/名家逝世/学唱豫剧等"与主题的互动事件"。

#### 维度5：长尾关键词总表

**文件：** `{赛道名}长尾关键词总表.yaml`

**数据来源：** 搜索关键词 + SEO数据 + 内容品类推导

**必含字段：**

- 按品类×受众分组
- 每组5-15个长尾关键词
- 高频搜索词单独列出

#### 维度6：标题公式库

**文件：** `{赛道名}标题公式库.yaml`

**数据来源：** 中老年赛道17种公式作为基础 + 竞品标题示例集分析 + 赛道特有公式补充

**必含字段：**

- 15-20种标题公式（结构模板+适用品类+适用受众+示例）
- 5-7类情感触发词（词表+适用品类+适用受众）

**适配要点：** 必须增加赛道特有公式。中老年有"年龄必知型"，豫剧有"身份认同型""名段解析型""抗战家国型"等。

#### 维度7：正向叙事模板

**文件：** `{赛道名}正向叙事模板.yaml`

**数据来源：** 基于受众敏感性推导

**必含字段：**

- 赋能型情感触发词表
- 3种以上赋能大纲模板
- 叙事基调选择规则表（条件→基调要求）

**适配要点：** 基调禁忌必须根据赛道受众敏感性设计。中老年有年龄焦虑禁忌（65-80岁禁纯焦虑），豫剧有名家逝世禁焦虑、抗战类禁焦虑等。

#### 维度8：写作风格库

**文件：** `{赛道名}写作风格库.md`

**数据来源：** 基于卡兹克"活人感"方法论 + 赛道特有风格参照物适配

**必含字段：**

- 13种写作手法详解（每种：说明+示例+适用场景）
- 赛道特有的风格适配提醒
- 绝对禁区（8条硬性禁令）
- 风格示例对比

**适配要点：** 中老年叫"活人感"，豫剧叫"戏味感"。核心理念相同（消除AI味），但参照物不同——中老年用邻里故事和日常口语，豫剧用戏曲专业知识的自然融入（曲牌知识随手掏、板式节奏断裂、戏迷口语转场等）。

#### 维度9：平台适配指南

**文件：** `{赛道名}平台适配指南.yaml`

**数据来源：** 6平台通用规格 + 赛道特有平台侧重

**必含字段：** 6平台的内容形式/标题风格/字数规格

**适配要点：** 不同赛道的平台侧重不同。中老年侧重微信+快手，豫剧侧重抖音+B站。

#### 维度10：竞品账号分析

**文件：** `{赛道名}竞品账号分析.yaml`

**数据来源：** 搜狗微信搜索采集的竞品数据

**必含字段：** 竞品账号数据（名称/定位/内容模式/受众）+ 差异化定位建议

#### 维度11：内容系列模板

**文件：** `{赛道名}内容系列模板.yaml`

**数据来源：** 基于中老年赛道模板结构推导

**必含字段：** 3种系列类型（时令/主题/事件）+ 排期表格式 + 创作流程

#### 维度12：去重机制

**文件：** `content_history.json`

**机制：** 近30篇创作记录，每次创作后追加，超过30条裁剪最旧的。

### 步骤7：赛道特有维度补充

12维度是基础集合。专业类赛道需要额外维度才能支撑足够深的选题空间：

| 赛道类型 | 需要的额外维度 | 豫剧示例 | 数据来源 |
|----------|---------------|---------|---------|
| 艺术类专业赛道 | 名家/流派档案 | 豫剧流派名家档案.yaml | 百科流派词条+六大名旦词条+Wikipedia |
| 艺术类专业赛道 | 经典作品库 | 豫剧经典剧目库.yaml | 百科代表剧目+Wikipedia剧目章节 |
| 艺术类专业赛道 | 技术体系详解 | 豫剧唱腔板式体系.yaml | 百科文化特征+二八板词条+搜索结果 |
| 所有赛道 | 爆款数据量化分析 | 豫剧爆款分析与传播数据.yaml | 搜狗微信搜索+抖音/B站数据 |
| 所有赛道 | 竞品标题示例集 | 豫剧公众号标题示例集.yaml | 搜狗微信搜索结果标题提取 |
| 所有赛道 | 视频资源索引 | 豫剧视频资源索引.yaml | 搜狗微信搜索+B站URL+媒体报道 |
| 地域性赛道 | 地域分支深度档案 | 豫剧地方名家深度档案.yaml | 专项搜索+澎湃新闻等媒体文章 |
| 有海外分支的赛道 | 海外专题 | 豫剧台湾专题.yaml | firecrawl搜索+百度百科+新华网 |

**补充时机：** 12维度先完成，额外维度在迭代优化中逐步补充。不必第一轮就全部完成。

## 第四阶段：SKILL.md编写

SKILL.md是调研的终态交付物之一，将12维度参考文件组织为可执行的创作流程。

### 步骤8：编写SKILL.md

**六阶段创作流程骨架（两个赛道验证过）：**

```
选题 → 创作 → 去重审核 → 风格增强 → 自检 → 保存
```

**SKILL.md必含模块：**

| 模块 | 说明 |
|------|------|
| front matter | name + description（触发词定义） |
| 概述 | 一句话总结六阶段流程 |
| 参考文件索引 | 每个文件的"何时读取"映射表——这是12维度文件与创作流程的桥梁 |
| 第一阶段：选题 | 步骤1-4（上下文确定→3-5选题生成→去重审核→呈现选择） |

| 约束条件 | 硬性约束列表 |
| 常见错误 | 错误→修正对照表 |

**description触发词编写规则：**

- 包含赛道名称核心关键词（如"中老年""豫剧""戏曲"）
- 包含常见话题关键词（如"花木兰""退休适应""失眠"）

## 目录命名与结构规范

### 核心分离原则

**SKILL 是只读技能资产，不含状态信息。** 所有带状态的数据（创作输出、创作历史）必须存放在 workspace 级别的隐藏目录中。.env 文件仅允许存在于 `workspace/.env`。

```
技能资产（只读）: {拼音}_{赛道中文}/         → references/ + scripts/ + 原调研资产/ + SKILL.md
运行时状态:      workspace/.{拼音}_{赛道中文}/ → outputs/ + content_history.json
环境变量:        workspace/.env               → 唯一允许的 .env 位置
```

### 目录命名规范

赛道调研资产目录统一放在项目根目录下，命名格式为 **`{拼音}_{赛道中文}`**：

```
saidao/                              # 项目根目录
  ├── zhonglaonian_中老年/           # 已完成赛道（只读技能资产）
  ├── yuju_豫剧/                     # 已完成赛道（只读技能资产）
  ├── xuanxue_玄学/                  # 进行中赛道
  ├── {拼音}_{赛道中文}/             # 新赛道目录（只读技能资产）
  ├── workspace/                     # 运行时状态目录
  │   ├── .zhonglaonian_中老年/      # 中老年赛道状态数据
  │   ├── .yuju_豫剧/                # 豫剧赛道状态数据
  │   ├── .{拼音}_{赛道中文}/        # 新赛道状态数据
  │   └── .env                       # 环境变量（唯一允许位置）
  ├── docs/                          # 方法论文档
  └── skills/                        # 创作技能（由调研资产蒸馏后部署）
```

**拼音规则：** 取赛道中文名称的标准拼音，小写，不加分隔符。"中老年"→`zhonglaonian`，"豫剧"→`yuju`，"玄学"→`xuanxue`。

**注意：** `skills/` 目录是创作技能的部署位置。调研资产本身存放在 `{拼音}_{赛道中文}/` 中。调研阶段不往 `skills/` 写内容。

## 蒸馏方法详解

### 从百科词条到参考文件的蒸馏逻辑

以豫剧赛道为例，展示典型的蒸馏过程：

#### 案例1：百度百科主词条（792行）→ 多个参考文件

**百度百科主词条包含：** 历史渊源8个时期、文化特征6项、角色行当、四大板类、代表剧目、传承保护、主要流派完整表、剧团分布、社会影响、梅花奖32位获奖者

**蒸馏去向：**

| 百科章节 | 蒸馏为 | 蒸馏方法 |
|----------|--------|---------|
| 历史渊源8时期 | 豫剧沿革历史品类数据（纳入交叉矩阵） | 提取8个时期节点，每个增加"内容创作角度" |
| 文化特征6项 | 豫剧唱腔板式体系.yaml | 提取四大板类，每个增加"常用场景"和"创作角度" |
| 角色行当 | 豫剧唱腔板式体系.yaml（行当体系部分） | 提取四生四旦四花脸，增加"表演要诀" |
| 代表剧目 | 豫剧经典剧目库.yaml | 提取剧目列表，每个增加"内容创作角度"（5-6个） |
| 主要流派表 | 豫剧流派名家档案.yaml | 提取20+个流派，增加"选题切入角度" |
| 梅花奖名单 | 豫剧流派名家档案.yaml（当代名家部分） | 32位获奖者完整名单 |
| 传承保护 | 豫剧全年节庆纪念日日历.yaml（非遗纪念日） | 提取非遗日等专项纪念日 |

**关键蒸馏决策：**

- 每个流派增加"选题切入角度"——中老年赛道没有这个字段，豫剧赛道需要
- 一字评价（美/劲/韵/脆/秀/巧）是百科六大名旦词条特有的文化资产，直接保留
- 剧目按题材分组而非简单列表——方便交叉选题推导
- 百科的角色行当提取后增加"表演要诀"——这些是极好的创作素材

#### 案例2：搜狗微信搜索（8轮）→ 竞品维度文件

**原始数据：** 约7,921条公众号文章标题

**蒸馏去向：**

| 数据 | 蒸馏为 | 蒸馏方法 |
|------|--------|---------|
| 竞品账号9个 | 豫剧竞品账号分析.yaml | 提取账号名+定位+内容模式+受众 |
| 标题约50+条 | 豫剧公众号标题示例集.yaml | 按类型分类（合集盘点/剧目推荐/名家专辑等8种） |
| 标题模式分析 | 豫剧标题公式库.yaml（补充赛道特有公式） | 从空白类型推导新公式 |
| 竞争空白6种 | 豫剧竞品账号分析.yaml（差异化定位） | 从未被使用的标题类型确认差异化空间 |

#### 案例3：专项搜索（刘忠河）→ 地方名家深度档案

**原始数据：** 搜狗微信搜索约2,325条 + 澎湃新闻210行深度文章

**蒸馏为：** 豫剧地方名家深度档案.yaml

**蒸馏方法：** 从深度文章中提取刘忠河完整档案（生卒/籍贯/流派/代表作/关键事件），增加"76岁唱爆北京城"等事件作为内容创作角度

## 常见陷阱

| 陷阱 | 说明 | 修正 |
|------|------|------|
| 照搬旧赛道分层 | 把中老年的年龄段直接用于新赛道 | 根据决策点1重新选择分层方式 |
| 品类过粗 | 只设5个品类导致选题空间太小 | 专业赛道至少10个品类 |
| 交叉组合不适配 | 直接复制中老年的交叉组合 | 根据赛道品类逻辑重新设计 |
| 忽略赛道专项纪念日 | 只用通用节气节日 | 必须增加赛道特有的纪念日 |
| 标题公式缺赛道特有公式 | 只用通用公式 | 从竞品空白推导赛道特有公式 |
| 风格体系照搬"活人感" | 所有赛道都用活人感 | 根据赛道命名特有感 |
| 叙事基调禁忌缺赛道特有规则 | 只保留年龄段焦虑禁忌 | 增加赛道特有禁忌 |
| 去重阈值一刀切 | 所有维度用相同阈值 | 品类≥5次/受众≥10次/标题公式≥3次降权≥5次禁用 |
| 不做首轮创作验证 | 建完库就认为完成 | 必须创作3-5篇验证 |
| 额外维度一步到位 | 第一轮就建所有维度 | 12维度先完成，额外维度逐步补充 |
| 调研资产写入skills/ | 调研阶段把数据写到skills目录 | 调研资产放 `{拼音}_{赛道中文}/`，skills/只用于最终技能部署 |
| 运行时状态写入SKILL目录 | 把outputs/content_history等带状态数据放进技能资产目录 | 状态数据必须放 `workspace/.{拼音}_{赛道中文}/`，SKILL目录只存放只读资产 |
| .env散落在多处 | 在子目录或技能目录中创建.env | .env仅允许存在于 `workspace/.env`，禁止其他位置 |
| 蒸馏照搬百科而非转化 | 直接复制百科词条内容 | 每个数据点增加"创作切入角度"，把百科数据转化为创作资源 |
| 删除原始抓取数据 | 蒸馏完成后删掉原调研资产 | 原调研资产保留，作为溯源和迭代补充的依据 |
